## 支援的支付方式

| 服務商 | 支付方式 | 說明 |
|--------|---------|------|
| **EasyPay（易支付）** | 支付寶、微信支付 | 相容易支付協議的第三方聚合支付 |
| **支付寶官方** | 桌面二維碼掃碼、移動端支付寶跳轉 | 直接對接支付寶開放平臺，桌面端返回二維碼，移動端返回 WAP/喚起連結 |
| **微信官方** | Native 掃碼、H5、公眾號/JSAPI 支付 | 直接對接微信支付 APIv3，按終端環境自動分流 |
| **Stripe** | 銀行卡、支付寶、微信支付、Link 等 | 國際支付，支援多幣種 |

> 支付寶官方 / 微信官方與易支付可以同時作為後臺服務商例項存在，但前臺始終只展示 `支付寶`、`微信支付` 兩個可見按鈕。管理員需要分別為這兩個按鈕選擇唯一支付來源：官方或易支付。官方渠道直接對接 API，資金直達商戶帳戶，手續費更低；易支付透過第三方平臺聚合，接入門檻更低。

> **易支付服務商推薦**：以下兩家均為相容易支付協議的第三方聚合支付，按資金通道與結算方式選擇：
>
> - **國內渠道 / 人民幣結算** — [ZPay](https://z-pay.cn/?uid=23808)（`https://z-pay.cn/?uid=23808`）：支付寶 / 微信官方 API 直連，手續費 **1.6%**；資金直達商家帳戶，**T+1 自動到帳**。支援**個人使用者**（無營業執照）每日 1 萬元以內交易；擁有營業執照則無限額。連結含 [Sub2ApiPay](https://github.com/touwaeriol/sub2apipay) 原作者 [@touwaeriol](https://github.com/touwaeriol) 的邀請碼，介意可去掉。
> - **國際渠道 / USDT 或美元結算** — [啟潤支付](https://kyren.top/?code=SUB2API)（`https://kyren.top/?code=SUB2API`）：為 AI 專案提供低門檻國際收款通道，支援國際版微信支付與支付寶，本地貨幣支付、美元結算。手續費：微信 2%、支付寶 2.5%；提現 0.1%（最低 40 美元、最高 150 美元），以 **USDT 或美元**到帳。無資質稽核、註冊即用，使用門檻最低；提現門檻略高，適合**不使用國內支付渠道、無法接受 Stripe 高達 6%+ 手續費、流水較大，且擁有美元或 USDT 渠道可接收提現資金**的使用者。啟潤支付開戶費 200 美元，透過本連結註冊（含 Sub2Api 作者 [@Wei-Shaw](https://github.com/Wei-Shaw) 邀請碼）可**免開戶費**，介意可去掉。
>
> 支付渠道的安全性、穩定性及合規性請自行鑑別，本專案不對任何第三方支付服務商做擔保或背書。

## 快速開始

1. 進入管理後臺 → **設定** → **支付設定** 標籤頁
2. 開啟 **啟用支付**
3. 配置基本引數（金額範圍、超時時間等）
4. 在 **服務商管理** 中新增至少一個服務商例項
5. 使用者即可在前端頁面進行充值

## 系統設定

在管理後臺 **設定 → 支付設定** 中配置以下引數：

### 基本設定

| 設定項 | 說明 | 預設值 |
|--------|------|--------|
| **啟用支付** | 啟用或停用支付系統 | 關閉 |
| **商品名字首** | 支付頁面顯示的商品名字首 | - |
| **商品名字尾** | 商品名字尾（如"元"） | - |
| **最低金額** | 單筆最低充值金額 | 1 |
| **最高金額** | 單筆最高充值金額（留空表示不限制） | - |
| **每日限額** | 每使用者每日累計充值上限（留空表示不限制） | - |
| **訂單超時時間** | 訂單超時分鐘數，至少 1 分鐘 | 30 |
| **最大待支付訂單數** | 同一使用者最大並行待支付訂單數 | 3 |
| **負載均衡策略** | 多服務商例項時的選擇策略 | 輪詢 |

### 前臺可見支付方式路由

當前版本對使用者統一展示支付方式，不區分官方渠道還是易支付：

- **支付寶**：後臺啟用後，需要額外指定該按鈕路由到 `支付寶官方` 或 `易支付支付寶`
- **微信支付**：後臺啟用後，需要額外指定該按鈕路由到 `微信官方` 或 `易支付微信`
- 同一個可見支付方式在同一時刻只能路由到一個來源
- 支付來源未選擇時，即使對應按鈕被開啟，前臺也不會暴露該支付方式

### 負載均衡策略

| 策略 | 說明 |
|------|------|
| **輪詢（round-robin）** | 按順序輪流分配到各服務商例項 |
| **最少金額（least-amount）** | 優先分配到當日累計金額最少的例項 |

### 取消頻率限制

防止使用者頻繁建立並取消訂單：

| 設定項 | 說明 |
|--------|------|
| **啟用限制** | 開關 |
| **視窗模式** | 滾動視窗 / 固定視窗 |
| **時間視窗** | 視窗長度 |
| **視窗單位** | 分鐘 / 小時 |
| **最大次數** | 視窗內允許的最大取消次數 |

### 幫助資訊

| 設定項 | 說明 |
|--------|------|
| **幫助圖片** | 充值頁面顯示的客服二維碼等圖片（支援上傳） |
| **幫助文本** | 充值頁面顯示的說明文字 |

## 服務商配置

每種服務商需要不同的憑證和引數。在 **服務商管理 → 新增服務商** 中選擇型別後填寫。

> **回撥地址自動生成**：新增服務商時，非同步回撥地址（Notify URL）和同步跳轉地址（Return URL）由系統根據你的站點域名自動拼接，無需手動填寫。管理員只需確認域名正確即可。

### EasyPay（易支付）

相容任何 EasyPay 協議的支付服務商。

| 引數 | 說明 | 必填 |
|------|------|------|
| **商戶 ID（PID）** | EasyPay 商戶 ID | 是 |
| **商戶金鑰（PKey）** | EasyPay 商戶金鑰 | 是 |
| **API 地址** | EasyPay API 基礎地址 | 是 |
| **支付寶通道 ID** | 指定支付寶通道（可選） | 否 |
| **微信通道 ID** | 指定微信通道（可選） | 否 |

### 支付寶官方

直接對接支付寶開放平臺。移動端走支付寶手機網站支付跳轉；桌面端優先使用當面付返回掃碼串，若商戶未開通當面付則回退到電腦網站支付，並將收銀臺連結同時返回給前端用於渲染二維碼或直接開啟支付頁。

| 引數 | 說明 | 必填 |
|------|------|------|
| **AppID** | 支付寶應用 AppID | 是 |
| **應用私鑰** | RSA2 應用私鑰 | 是 |
| **支付寶公鑰** | 支付寶公鑰 | 是 |

### 微信官方

直接對接微信支付 APIv3，支援 Native 掃碼支付、H5 支付，以及在微信環境內的公眾號/JSAPI 支付。

| 引數 | 說明 | 必填 |
|------|------|------|
| **AppID** | 微信支付 AppID | 是 |
| **商戶號（MchID）** | 微信支付商戶號 | 是 |
| **商戶 API 私鑰** | 商戶 API 私鑰（PEM 格式） | 是 |
| **APIv3 金鑰** | 32 位 APIv3 金鑰 | 是 |
| **微信支付公鑰** | 微信支付公鑰（PEM 格式） | 是 |
| **微信支付公鑰 ID** | 微信支付公鑰 ID | 是 |
| **商戶證書序列號** | 商戶證書序列號 | 是 |

### Stripe

國際支付平臺，支援多種支付方式和幣種。

| 引數 | 說明 | 必填 |
|------|------|------|
| **Secret Key** | Stripe 金鑰（`sk_live_...` 或 `sk_test_...`） | 是 |
| **Publishable Key** | Stripe 可公開金鑰（`pk_live_...` 或 `pk_test_...`） | 是 |
| **Webhook Secret** | Stripe Webhook 簽名金鑰（`whsec_...`） | 是 |

## 服務商例項管理

同一種服務商可以建立**多個例項**，實現負載均衡和風控：

- **多例項負載均衡** — 按輪詢或最少金額策略分流訂單
- **獨立限額** — 每個例項可獨立配置單筆最小/最大金額和每日限額
- **獨立啟停** — 可單獨啟用/停用某個例項，不影響其他例項
- **退款控制** — 每個例項可單獨開啟或關閉退款功能
- **支付方式** — 每個例項可選擇支援的支付方式子集
- **排序** — 拖拽調整例項順序

### 例項限額配置

每個例項支援以下限額：

| 限額項 | 說明 |
|--------|------|
| **單筆最小金額** | 該例項接受的最小訂單金額 |
| **單筆最大金額** | 該例項接受的最大訂單金額 |
| **每日限額** | 該例項每日累計交易上限 |

> 負載均衡時，系統會自動跳過超出限額的例項。

## Webhook 配置

支付回撥是支付系統的核心環節，必須正確配置：

### 回撥地址格式

新增服務商時，系統會自動根據站點域名拼接回調地址，格式如下：

| 服務商 | 回撥路徑 |
|--------|---------|
| **EasyPay** | `https://your-domain.com/api/v1/payment/webhook/easypay` |
| **支付寶官方** | `https://your-domain.com/api/v1/payment/webhook/alipay` |
| **微信官方** | `https://your-domain.com/api/v1/payment/webhook/wxpay` |
| **Stripe** | `https://your-domain.com/api/v1/payment/webhook/stripe` |

> 將 `your-domain.com` 替換為你的實際域名。EasyPay / 支付寶 / 微信的回撥地址在新增服務商時自動填入，無需手動配置。

### Stripe Webhook 設定

1. 登入 [Stripe Dashboard](https://dashboard.stripe.com/)
2. 進入 **Developers → Webhooks**
3. 新增端點，填寫回撥地址
4. 訂閱事件：`payment_intent.succeeded`、`payment_intent.payment_failed`
5. 將生成的 Webhook Secret（`whsec_...`）填入服務商配置

### 注意事項

- 回撥地址必須是 **HTTPS**（Stripe 強制要求，其他服務商強烈推薦）
- 確保伺服器防火牆允許支付平臺的回撥請求
- 系統會自動進行簽名驗證，防止偽造回撥
- 支付成功後自動完成餘額充值，無需人工幹預

## 支付流程

```
使用者選擇充值金額和支付方式
       │
       ▼
  建立訂單 (PENDING)
  ├─ 校驗金額範圍、待支付訂單數、每日限額
  ├─ 負載均衡選擇服務商例項
  └─ 呼叫服務商獲取支付資訊
       │
       ▼
  使用者完成支付
  ├─ EasyPay    → 掃碼 / H5 跳轉
  ├─ 支付寶官方  → 桌面掃碼單（當面付優先，電腦網站支付回退）/ 移動端支付寶跳轉
  ├─ 微信官方    → 桌面 Native 掃碼 / 非微信 H5 / 微信內 JSAPI
  └─ Stripe     → Payment Element（銀行卡/支付寶/微信等）
       │
       ▼
  支付回撥驗籤 → 訂單 PAID
       │
       ▼
  自動充值到使用者餘額 → 訂單 COMPLETED
```

### 訂單狀態說明

| 狀態 | 說明 |
|------|------|
| `PENDING` | 待支付，等待使用者完成支付 |
| `PAID` | 已支付，等待充值到帳 |
| `COMPLETED` | 已完成，餘額已到帳 |
| `EXPIRED` | 已過期，超時未支付 |
| `CANCELLED` | 已取消，使用者主動取消 |
| `FAILED` | 充值失敗，可管理員重試 |
| `REFUND_REQUESTED` | 已申請退款 |
| `REFUNDING` | 退款處理中 |
| `REFUNDED` | 已退款 |

### 超時與兜底

- 訂單超時後，後臺任務會先查詢上游支付狀態再標記過期
- 如果使用者實際已支付但回撥延遲，系統會透過查詢補單
- 後臺任務每 60 秒執行一次超時檢查

## 從 Sub2ApiPay 遷移

如果你之前使用 [Sub2ApiPay](https://github.com/touwaeriol/sub2apipay) 作為外部支付系統，現在可以遷移到內建支付：

### 主要差異

| 對比項 | Sub2ApiPay | 內建支付 |
|--------|-----------|---------|
| 部署方式 | 獨立服務（Next.js + PostgreSQL） | 內建於 Sub2API，無需額外部署 |
| 支付方式 | EasyPay、支付寶、微信、Stripe | 相同 |
| 配置方式 | 環境變數 + 獨立管理後臺 | Sub2API 管理後臺內統一配置 |
| 充值對接 | 透過 Admin API 回撥 | 內部直接處理，更可靠 |
| 訂閱套餐 | 支援 | 暫不支援（計劃中） |
| 訂單管理 | 獨立管理介面 | 整合在 Sub2API 管理後臺 |

### 遷移步驟

1. 在 Sub2API 管理後臺啟用支付並配置服務商（使用相同的支付憑證）
2. 更新 Webhook 回撥地址為 Sub2API 的回撥地址
3. 確認新訂單透過內建支付正常處理
4. 停用 Sub2ApiPay 服務

> **注意**：Sub2ApiPay 中的歷史訂單資料不會自動遷移。建議保留 Sub2ApiPay 一段時間以便查詢歷史記錄。
